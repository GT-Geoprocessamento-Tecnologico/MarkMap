# Synchronization protocol

The canonical JSON schemas live in `@geonexo/contracts`. A client sends `PushSyncRequest` to `POST /api/v1/sync/push` and reads `PullSyncResponse` from `GET /api/v1/sync/pull?cursor=...&limit=...`. The bearer scopes both endpoints to one anonymous workspace. The cursor is the opaque string `v1.<base64url-payload>.<base64url-HMAC-SHA256>`; the signed payload contains the workspace UUID and committed sequence. The API verifies the MAC and checks the embedded workspace against the workspace derived from the bearer before querying. It never accepts a client-supplied workspace ID for pull scope.

Push operations are immutable. An upsert carries a bounded entity payload, expected `baseVersion`, and optional predecessor; a delete carries no payload. Operation IDs are idempotency keys. Reusing an ID with a different envelope is rejected, while replaying an accepted operation returns its original version and sequence in `alreadyApplied`. A version or scope failure is represented by a typed conflict and does not silently rewrite later local operations. A `SCOPE_REJECTED` conflict uses `serverVersion: 0` and omits `serverPayload`; a `VERSION_CONFLICT` carries a positive server version.

Pull uses an opaque, workspace-bound cursor whose initial internal sequence is `"0"`. The server assigns commit sequence values and signs the cursor after each page. Clients apply every page and its next cursor atomically. An empty page preserves the input cursor, and the final page keeps its last sequence even when `hasMore` is false. Tombstones remain explicit so deletes cannot be resurrected by an older page.

The protocol bounds batch size, metadata, IDs, strings, feature geometry (at most 10,000 coordinate positions), and blob references. Payload and discriminant entity IDs must agree; delete envelopes cannot contain a payload. Unknown fields are rejected at the new wire boundary. A `SCOPE_REJECTED` conflict must not contain `serverPayload`, preventing disclosure of another workspace's data. PDF imports reference immutable, checksummed local blobs and never embed bytes in sync JSON. The API body limit is 1 MiB; runtime must enforce it before parsing and apply the geometry cap before database work.

The current contract validates cursor and capability token syntax only. The server-side HMAC verification, CSPRNG generation, constant-time secret comparison, provisioning/recovery/revocation, workspace-scoped transactions, idempotency receipts, and upload checksum verification are implementation gates; none is claimed as implemented by this contract freeze.
